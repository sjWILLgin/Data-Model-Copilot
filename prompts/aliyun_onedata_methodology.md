# 阿里云 / 阿里巴巴 OneData 建模方法论摘要

本文件是 ModelFlow 提示词包的方法论基线。线上调用大模型时，应优先将本文件与 `_shared_system.md` 一起作为 system/developer 上下文注入。

## 1. 数仓分层

遵循阿里云 DataWorks / MaxCompute / Hologres 文档中的通用分层思想：

1. ODS（Operational Data Store，数据引入层 / 操作数据层）
   - 存放从源业务系统同步来的原始数据。
   - 结构尽量与源系统保持一致。
   - 可记录基础数据历史变化。
   - 不应承载复杂公共口径。

2. CDM（Common Data Model，数据公共层 / 通用数据模型层）
   - 由 ODS 加工整合而来。
   - 负责建立一致性维度、可复用明细事实、公共粒度汇总指标。
   - CDM 内通常包含 DIM、DWD、DWS。

3. DIM（Dimension，公共维度层）
   - 建设企业一致性维度。
   - 描述业务对象属性，例如客户、商品、组织、员工、供应商、门店、账户、产品。
   - 重点关注主键、自然键、代理键、层级、枚举、当前/历史属性、SCD/拉链。

4. DWD（Data Warehouse Detail，明细数据层）
   - 围绕业务过程设计，保留最原子、最细粒度的明细事实。
   - 保存业务发生现场，包括事实度量、退化维度、关联维度键、业务时间、状态。
   - 是后续 DWS、ADS 和分析复用的基础。

5. DWS（Data Warehouse Summary / Service，汇总数据层）
   - 面向分析主题对象和公共指标需求建设。
   - 基于 DWD 和 DIM 形成公共粒度汇总事实、主题宽表、周期快照、累积快照。
   - 不应绕过 DWD 直接从 ODS 拼应用宽表。

6. ADS（Application Data Service，应用数据层）
   - 面向具体应用、报表、接口、驾驶舱、算法服务。
   - 优先消费 CDM，避免直接重复加工 ODS。

## 2. 规范建模对象

参考 Dataphin 规范建模思想，模型设计应从概念模型和业务语义开始：

1. 业务板块 / 业务分类。
2. 数据域。
3. 业务过程。
4. 业务对象。
5. 维度逻辑表。
6. 事实逻辑表。
7. 原子指标。
8. 业务限定。
9. 派生指标 / 复合指标。
10. 汇总逻辑表。

## 3. 事实表设计原则

事实表是维度建模的核心，应围绕业务过程设计。

### 3.1 事实类型

1. 事务型事实表：记录业务过程在某一时间点发生的原子事件。
2. 周期快照事实表：按固定周期记录状态或余额。
3. 累积快照事实表：记录一个业务生命周期中多个关键里程碑时间。
4. 无事实事实表：记录事件发生本身，不一定有金额/数量度量。

### 3.2 度量可加性

1. 可加事实：金额、数量、次数等可跨多数维度求和。
2. 半可加事实：库存余额、账户余额、人数快照等不可跨时间简单求和。
3. 不可加事实：比例、单价、率值等通常不能直接求和。

### 3.3 设计约束

1. 先声明事实表粒度，再选择事实和维度。
2. 尽可能包含与业务过程有关的事实。
3. 保留业务过程发生时的上下文。
4. 高频过滤、分析所需的退化维度可保存在事实表中。
5. 不同粒度事实不得混放，除非有明确聚合、透视或桥接逻辑。

## 4. 维度表设计原则

1. 建设一致性维度，支撑跨主题复用。
2. 明确维度主键、自然键、业务唯一键和代理键。
3. 明确维度层级，例如组织层级、商品品类层级、区域层级。
4. 明确当前属性与历史属性。
5. 对会变化的维度，判断是否需要 SCD2 / 拉链 / 快照。
6. 枚举类字段可沉淀为枚举维度或公共字典。
7. 主数据优先作为维度来源，但需处理重复、合并、拆分、失效和黄金记录。

## 5. DWS 汇总设计原则

1. DWS 以分析主题对象作为建模驱动。
2. 汇总粒度必须清晰，例如客户-日、商品-门店-日、组织-月、订单一行。
3. 指标必须来源于 DWD 明细或 DIM 维度，不应直接重复加工 ODS。
4. 公共指标需要沉淀统计周期、业务限定、口径说明和质量规则。
5. 宽表不是任意字段拼接，必须说明主粒度和非主粒度字段的处理逻辑。

## 6. 跨层调用规范

1. ADS 优先读取 DWS / DWD / DIM，不应绕过公共层直接读取 ODS。
2. DWS 优先基于 DWD + DIM 汇总。
3. DWD 可读取 ODS，并做清洗、标准化、轻度整合。
4. DIM 可读取 ODS / 主数据 / 字典源，并形成一致性维度。
5. 若必须跨层读取，需要输出风险和原因。

## 7. 各业务域建模关注点

### 7.1 销售业绩

对象：客户、门店、销售人员、商品、渠道、区域。

过程：下单、支付、发货、退货、拜访、目标下达。

关注：订单头/明细粒度、成交/发货/回款口径、退货冲减、目标与实际匹配、渠道归因、销售归属历史。

### 7.2 供应链

对象：供应商、物料、SKU、仓库、批次、路线。

过程：采购、入库、出库、调拨、盘点、库存快照。

关注：批次/效期、库存快照半可加、单位换算、订单/明细/批次粒度、仓库归属。

### 7.3 财务

对象：科目、成本中心、供应商、客户、合同、发票。

过程：凭证、开票、付款、收款、报销、计提、结转。

关注：会计期间、币种、税额、借贷方向、红冲、分摊、权责发生制。

### 7.4 人资

对象：员工、人员、组织、岗位、职级。

过程：入职、转岗、离职、考勤、绩效、培训。

关注：当前组织 vs 发生时组织、状态历史、人员主数据、组织层级、有效期。

### 7.5 用人费用

对象：员工、组织、成本中心、项目、薪资项。

过程：薪资发放、奖金、社保公积金、成本分摊。

关注：薪资周期、费用归属期、成本中心分摊、项目分摊、敏感数据权限。

### 7.6 产品

对象：SPU、SKU、品类、品牌、价格、生命周期阶段。

过程：上架、下架、调价、促销、生命周期变更。

关注：SKU/SPU 粒度、品类历史、价格有效期、促销叠加。

### 7.7 主数据

对象：客户、供应商、商品、组织、员工、字典。

过程：创建、更新、合并、拆分、停用、启用。

关注：黄金记录、自然键、代理键、有效期、合并拆分关系、重复记录。
