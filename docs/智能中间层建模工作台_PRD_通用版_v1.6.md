# 智能中间层建模工作台 PRD（通用版 v1.6）

## 1. 产品基本信息

### 1.1 产品名称

智能中间层建模工作台

可选英文名：ModelFlow / Data Model Copilot

内部简称：模型工作台

### 1.2 产品定位

智能中间层建模工作台是一个面向数据产品经理、数据 BP、数据开发、业务方和数据治理团队的 AI 辅助建模产品。产品通过输入 ODS / DWD / DIM 表结构、目标字段、建表语句、Excel 字段清单、样例数据和业务调研内容，调用可配置的大模型，对业务对象、业务活动、事件过程、字段语义、模型粒度、字段映射、口径风险、缺失项和疑问点进行分析，辅助用户完成从业务需求到 CDM 中间层模型设计的全过程。

该产品不是简单的自动拼表工具，而是基于数仓分层、规范建模和人机协同确认机制，帮助团队标准化完成模型方案选择、字段口径确认、疑问闭环和交付物生成。

### 1.3 一句话说明

通过大模型对来源表和目标字段进行语义识别、建模推理和字段映射，结合用户确认和疑问闭环，生成可追溯、可编辑、可导出的中间层模型设计成果。

---

## 2. 背景与问题

### 2.1 当前业务背景

企业数据建设过程中，业务系统会沉淀大量 ODS 表。数据产品在建设中间层时，经常需要基于多个业务底表判断是否可以建设某个 CDM / DWD / DWS / ADS 模型。

该场景不限于人资招聘，也可能发生在销售过程、客户管理、供应链、费用报销、商品运营、渠道管理、售后服务、生产制造等业务域。不同业务域的表名、字段名和口径不同，但建模过程存在共性：识别业务对象、识别业务活动、判断事件过程、确定主粒度、映射字段来源、标注疑问、生成交付物。

### 2.2 现有痛点

1. ODS 表语义难判断，仅靠字段名和注释容易误判。
2. 字段相似不代表可以直接建模，还需要判断来源可靠性、业务时点、枚举字典、一对多关系和取数规则。
3. 目标字段经常混合多个业务粒度，例如业务对象粒度、单据粒度、事件明细粒度、组织粒度和汇总指标粒度。
4. 当前口径和历史口径缺少显式确认，例如组织、负责人、客户、商品、门店等会变化的维度。
5. 疑问点分散在会议、聊天和 Excel 备注中，缺少结构化闭环。
6. 交付物格式不统一，字段映射、DDL、SQL、疑问清单、枚举字典和质量规则经常缺失。
7. 如果只做字段拼接，容易绕过公共层建设，无法沉淀可复用数据资产。

## 3. 产品目标

### 3.1 总体目标

建设一个通用 AI 辅助中间层建模工作台，将数据产品在 ODS 到 CDM 建模中的经验流程产品化，实现从表结构输入、AI 模型配置、语义识别、模型推荐、目标模型选择、字段映射、疑问确认、AI 复核到交付物导出的闭环。

### 3.2 业务目标

1. 降低字段梳理、口径整理和疑问标注成本。
2. 提高 ODS 到 CDM 建模判断的准确性、规范性和可追溯性。
3. 让业务、BP、数据产品、开发在同一页面确认口径。
4. 将一次性 Excel 交付升级为可复用模型资产。
5. 通过 AI 深度分析减少遗漏字段、误判口径和后续返工。

### 3.3 产品目标

1. 支持上传 SQL / TXT / CSV / XLSX 表结构文件。
2. 支持下载标准表结构填写模板。
3. 支持一次粘贴多个 CREATE TABLE 建表语句。
4. 支持 AI 模型配置中心，按任务阶段选择不同供应商和模型。
5. 支持 AI 识别表语义、字段语义、业务对象、业务活动和事件过程。
6. 支持推荐 DIM / DWD / DWS / ADS 等模型方案。
7. 支持在 CDM 推荐页单选唯一目标模型，并允许自定义目标表名、中文名、分层、模型类型和粒度。
8. 支持字段映射、可行性判断、取值逻辑和置信度展示。
9. 支持疑问中心补充口径后，触发大模型重新复核字段映射。
10. 支持展示大模型分析进度和当前使用的模型配置。
11. 支持导出 Excel、PRD、DDL、SQL 草稿、疑问清单和枚举字典。

## 4. 产品设计原则

### 4.1 通用优先

产品不得绑定某一个业务域。人资、销售、客户、供应链、费用、商品等只作为业务域选项或示例，核心规则必须围绕通用建模概念：业务对象、业务活动、事件过程、维度、事实、粒度、口径、字典、血缘。

### 4.2 AI 不是最终决策者

大模型负责预判、推理、识别、建议和生成疑问。目标模型选择、表名、粒度、口径、是否纳入本期等关键决策必须由用户确认。

### 4.3 目标模型必须单选

CDM 模型推荐页可以展示多个候选方案，但当前建模任务最终只能选定一个目标模型和一个目标表名。DIM / DWD / DWS / ADS 方案可作为候选建议，最终 DDL、SQL、PRD 和 Excel 交付物必须使用用户单选的目标模型。

### 4.4 不确定即标注疑问

对于字段含义、枚举来源、时间口径、组织口径、Join 粒度、一对多展开和缺表问题，系统不能强行生成结论，应标注为待确认。

### 4.5 疑问必须闭环

疑问中心不是静态列表。用户补充业务口径后，应可以提交给大模型重新判断字段映射合理性，并返回字段映射工作台查看复核后的来源、逻辑、可行性、置信度和状态。

### 4.6 输出必须可追溯

每个目标字段都必须能追溯到来源表、来源字段、加工逻辑、枚举转换、确认状态和疑问记录。

### 4.7 密钥不放前端

AI 模型配置中心可以在前端配置供应商、Base URL、模型名和密钥引用名，但生产环境不得把真实 API Key 存在浏览器。真实调用应由后端读取环境变量并代理执行。

## 5. 用户角色

### 5.1 数据产品经理

创建模型任务、上传表结构、配置 AI 模型、查看预分析结果、选择目标模型、确认字段口径、生成交付物。

### 5.2 数据 BP

补充业务场景、指标口径、字段含义和业务确认项，参与疑问确认。

### 5.3 数据开发

查看字段映射、DDL、SQL 草稿、Join 逻辑、数据质量规则和缺失项，基于交付物进行开发。

### 5.4 业务方

确认业务口径，包括字段是否需要、口径如何定义、当前/历史口径如何选择、缺失字段是否本期建设。

### 5.5 数据治理 / 管理者

查看模型资产、模型状态、缺失字典、重复建设、口径变更和上线情况。

## 6. 核心使用场景

### 6.1 目标表驱动模式

用户已有目标字段，希望上传若干来源表结构，让系统判断底表是否可以支撑目标模型。

流程：

1. 新建模型任务。
2. 输入目标字段。
3. 上传或粘贴来源表结构。
4. 配置 AI 模型与调用策略。
5. AI 预分析表语义、字段语义和风险。
6. 系统推荐候选 CDM 模型。
7. 用户单选目标模型并可自定义表名、层级和粒度。
8. 进入字段映射工作台。
9. 用户处理疑问并触发 AI 复核。
10. 导出交付物。

### 6.2 底表驱动模式

用户只有一组 ODS 表，不确定能建设什么中间层模型。

系统基于表结构识别业务对象、业务活动和事件过程，推荐候选模型，用户从中单选目标模型。

### 6.3 共创调研模式

数据产品和 BP 与业务方边调研边录入目标字段、筛选条件和业务规则，系统实时提示需要补充的口径和缺失来源。

### 6.4 模型评审模式

用户上传已有 DDL / SQL / 字段清单，系统检查模型粒度、字段来源、字典、口径、Join 风险和质量规则。

## 8. 整体业务流程

1. 用户进入模型任务列表。
2. 点击新建模型。
3. 选择业务域、建模模式、期望层级和目标字段。
4. 上传 SQL / TXT / CSV / XLSX，或下载模板填写后上传。
5. 如使用 DDL，可一次粘贴多个 CREATE TABLE，建议用英文分号分隔。
6. 进入 AI 模型配置中心。
7. 选择不同任务阶段使用的模型供应商和模型名。
8. 点击 AI 预分析。
9. 系统展示分析进度和当前模型配置。
10. 系统生成表语义、字段语义、业务过程、风险提示。
11. 系统推荐多个 CDM 候选模型。
12. 用户单选唯一目标模型。
13. 用户可编辑目标模型表名、中文名、分层、模型类型和粒度。
14. 进入字段映射工作台。
15. 用户查看目标字段到来源字段的映射。
16. 系统生成疑问清单。
17. 用户在疑问中心补充口径、修改状态。
18. 用户提交给大模型复核。
19. 系统展示复核进度。
20. 复核完成后返回字段映射工作台。
21. 用户确认后进入交付物导出。
22. 系统按用户单选的目标模型生成交付物。

## 9. 页面与功能设计

## 9.1 页面一：新建模型任务

### 页面目标

完成模型任务基础信息填写。

### 字段

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|---|---|
| 任务名称 | 输入框 | 是 | 例如：通用业务过程分析模型 |
| 业务域 | 下拉框 | 是 | 通用业务域、销售过程、客户管理、费用管理、供应链、人资管理等 |
| 建模模式 | 单选 / 下拉 | 是 | 目标表驱动、底表驱动、共创调研、模型评审 |
| 期望层级 | 单选 / 下拉 | 否 | DIM、DWD、DWS、ADS、让 AI 判断 |
| 目标字段 | 文本域 | 是 | 支持中文逗号、顿号、换行、Tab 分隔 |

### 交互

1. 用户填写任务信息后进入上传解析。
2. 目标字段会自动生成建议英文名、字段类型和优先级。

---

## 9.2 页面二：表结构上传与解析

### 页面目标

支持用户通过文件上传、模板填写或粘贴 DDL 的方式录入来源表结构。

### 输入方式

1. 上传 SQL / TXT。
2. 上传 CSV / TSV 字段清单。
3. 上传 XLSX / XLS 模板或字段清单。
4. 粘贴一个或多个 CREATE TABLE 建表语句。
5. 下载标准表结构模板填写后上传。

### 表结构模板

模板文件名：智能中间层建模_表结构填写模板.xlsx

包含 Sheet：

1. 字段清单。
2. 表级信息。
3. 枚举字典。
4. 填写说明。

字段清单建议列：

| 列名 | 说明 |
|---|---|
| 表英文名* | 来源表英文名 |
| 表中文名/注释 | 表中文名或表注释 |
| 字段英文名* | 字段英文名 |
| 字段中文名/注释* | 字段中文名或字段注释 |
| 数据类型* | bigint、varchar、datetime、decimal 等 |
| 是否主键 | 是 / 否 |
| 是否可空 | 是 / 否 |
| 默认值 | 字段默认值 |
| 是否分区字段 | 是 / 否 |
| 枚举值说明 | 例如 1:线上;2:线下 |
| 样例值 | 字段样例 |
| 字段来源说明 | 业务系统、主数据、字典表等 |
| 业务口径备注 | 用户补充口径 |

### 多 DDL 粘贴规则

1. 支持一次粘贴多个 CREATE TABLE。
2. 推荐每个 CREATE TABLE 以英文分号 ; 结束。
3. 没有分号时，系统按下一个 CREATE TABLE 自动识别。
4. 支持空行和注释分隔。
5. 字段类型里的括号不应误拆，例如 varchar(64)、decimal(18,2)。

### 解析内容

| 内容 | 说明 |
|---|---|
| 表名 | 来源表英文名 |
| 表中文名 / 注释 | 来源表业务含义 |
| 字段名 | 原始字段名 |
| 字段注释 | COMMENT 或模板填写内容 |
| 数据类型 | 字段类型 |
| 是否主键 | 根据 DDL 或模板判断 |
| 是否可空 | 根据 DDL 或模板判断 |
| 枚举信息 | 从字段注释或模板抽取 |
| 疑似字段类型 | 主键、时间、状态、枚举、组织、人员、金额、事件等 |

## 9.3 页面三：AI 模型配置中心

### 页面目标

支持为不同建模任务阶段配置不同大模型、供应商和调用策略。

### 供应商配置

| 配置项 | 说明 |
|---|---|
| 供应商名称 | OpenAI、通义千问、DeepSeek、企业私有模型、自定义网关 |
| 接口类型 | OpenAI Compatible、Private Gateway 等 |
| Base URL | 模型服务地址 |
| 密钥引用名 | 后端环境变量名，例如 OPENAI_API_KEY |
| 是否启用 | 是否参与任务分配 |

### 任务模型分配

| 任务 | 说明 |
|---|---|
| 表/字段语义识别 | 识别表含义和字段类型 |
| CDM 建模推理 | 判断分层、模型类型、粒度 |
| 字段映射复核 | 对字段来源、逻辑和可行性重新判断 |
| SQL 草稿生成 | 生成开发参考 SQL |
| PRD / Excel 生成 | 生成交付说明 |
| 模型质量评审 | 检查粒度、字典、Join 和口径风险 |

### 调用策略

| 策略 | 说明 |
|---|---|
| 快速模式 | 快速字段匹配和初步判断 |
| 标准模式 | 常规建模推荐和字段口径生成 |
| 深度模式 | 多轮推理、输出更完整建模方案 |
| 保守模式 | 不确定内容全部标疑问 |
| 成本优先 | 优先低成本模型 |
| 准确性优先 | 优先强推理模型 |
| 私有安全优先 | 只调用企业内网模型 |

### 安全原则

1. 前端只保存供应商配置和密钥引用名。
2. 真实 API Key 应保存在后端环境变量。
3. 前端通过后端接口发起 AI 请求。
4. 后端负责审计、限流、脱敏和日志记录。

## 9.4 页面四：AI 预分析报告

### 页面目标

上传表结构后，AI 输出整体建模预判报告，而不是直接生成宽表。

### 进度展示

系统需要展示：

1. 当前任务阶段。
2. 当前使用模型供应商。
3. 当前模型名。
4. 当前调用策略。
5. 不确定性处理策略。

### 报告模块

#### 表语义识别

| 表名 | AI 判断 | 表类型 | 置信度 | 判断依据 |
|---|---|---|---|---|
| ods_business_order | 通用业务单据表 | 业务活动表 | 高 | 包含单据 ID、对象、发生时间、状态 |
| ods_business_event_record | 通用业务事件记录表 | 事件/流程记录表 | 高 | 包含事件类型、事件时间、结果 |

#### 字段语义识别

字段类型包括：

1. 主键 / 外键。
2. 时间字段。
3. 状态 / 枚举字段。
4. 组织字段。
5. 人员 / 负责人字段。
6. 金额字段。
7. 数量字段。
8. 描述字段。
9. 事件 / 流程字段。
10. 业务属性字段。

#### 建模风险提示

1. 多粒度字段混用。
2. 当前值与业务发生时值不清。
3. 编码字段缺少字典。
4. 事件记录一对多，需要聚合或横向展开。
5. 部分字段无法由当前表支撑。
6. 部分字段可能不适合放入同一张目标表。

## 9.5 页面五：CDM 模型推荐

### 页面目标

基于 AI 预分析和建模规则，推荐候选 CDM 模型方案，并让用户单选唯一目标模型。

### 核心原则

1. 可以推荐多个候选模型。
2. 当前任务最终只能选择一个目标模型。
3. 目标模型决定最终目标表名。
4. 用户必须可以自定义表名、中文名、分层、模型类型和粒度。
5. 交付物必须使用用户选择的目标模型，而不是系统默认决定。

### 页面字段

| 字段 | 说明 |
|---|---|
| 是否目标模型 | 单选 |
| 模型表名 | 可编辑 |
| 中文名 | 可编辑 |
| 分层 | DIM / DWD / DWS / ADS / 待判断 |
| 模型类型 | 维度表、事务事实表、事件事实表、主题宽表、快照表等 |
| 粒度 | 可编辑，例如一条业务单据一行 |
| 推荐程度 | 高、中高、可选 |

### 推荐模型示例

| 模型表名 | 中文名 | 分层 | 模型类型 | 粒度 | 推荐 |
|---|---|---|---|---|---|

提示词设计原则：

1. 通用优先，不绑定人资单一场景。

3. 所有任务输出结构化 JSON，便于后端校验和前端渲染。
4. CDM 模型推荐只能推荐候选方案，最终目标模型必须由用户单选。
5. 字段映射不能凭字段名强行匹配，必须考虑语义、粒度、时间口径、字典和来源可靠性。
6. 疑问中心用户补充口径后，必须通过 question_review 提示词重新复核映射。
7. 真实 API Key 不进入提示词和前端，只由后端环境变量管理。
